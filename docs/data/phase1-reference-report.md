## Mechanical rules

- **crosswalk** `fcst_validation.forecast_run_id`: Forecast runs are keyed per run and horizon; validations carry the horizon in horizon_bucket_hours.
- **crosswalk** `reliability_life_history.asset_id`: Module-level life history cites serialised PV modules, which become PV module records, not assets.
- **null-token** `pno_resources.crew_id` ~ `^N/A$`: Resources that are not crews (vehicles, equipment) carry N/A; stored as null.
- **aggregate** `*.plant_id` ~ `^PORTFOLIO$`: Portfolio-level rows become projections in phase 3, not site rows.
- **merge** `plan_interventions.intervention_id` ~ `^INT-PV-`: PV module interventions exist only in the plan register; resolved by the phase 2 intervention merge.
- **merge** `plan_requirements.intervention_id` ~ `^INT-PV-`: Requirements of the PV module interventions; resolved by the phase 2 intervention merge.
- **merge** `msi_spare_requirements.intervention_id` ~ `^INT-PV-`: Spares for the PV module interventions; resolved by the phase 2 intervention merge.
- **merge** `plan_scenarios.scenario_id`: Plan scenarios are a second scenario register; resolved by the phase 2 scenario merge.
- **merge** `spare_parts_master.part_id`: Second part master; resolved by the phase 2 part merge.
- **merge** `sus_hse_events.event_id` ~ `^HSE-`: HSE incidents have their own ID space; phase 2 moves them to hse_incident.
